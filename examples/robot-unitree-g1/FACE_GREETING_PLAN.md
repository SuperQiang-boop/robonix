# G1 移动中人脸识别迎宾实施计划

> 当前实现状态（2026-09-28）：第一阶段代码已落地为“事件触发播报与手臂动作”，但
> 尚未实现静止/导航状态读取，因此不能保证只在机器人静止时迎宾。`navigation_enabled`
> 和 `turn_to_face_enabled` 已加入配置，当前打开会被拒绝；skill 不调用导航或转向。
> 人脸服务输出确认事件，内置语音迁移到 `g1_face_greeting`。真实 G1 端到端验收未完成。

## 实施状态（2026-09-28）

- **已落地：**档案可保存注册亲密度和累计见面次数并计算当前等级；识别服务输出确认事件，不直接播报；迎宾 skill 按等级映射动作、调用 speech、去重并做冷却。
- **已落地：**迎宾配置提供导航和转向开关占位；两项必须为 `false`。MCP client 依赖声明要求 FastMCP client extra，MCP v1/FastMCP v3 主版本范围。
- **当前重要限制：**迎宾 skill 没有订阅导航状态，也没有静止检测/运动互锁。即使开关关闭，检测到的人脸事件仍会触发播报和挥手；部署方必须只在确认机器人静止、不执行导航时启用此 skill。
- **待实现：**机器人静止/安全状态门禁；可靠导航 pause/resume 和暂停所有权；相机 bearing 标定及转向；相应仿真、故障注入和实机验收。

## 目标

G1 正在执行导航任务时，若稳定识别到注册人员，则安全暂停当前移动，面向该人员播报个人问候语，并根据注册档案中的亲密度执行相应手部动作；迎宾完成或发生可恢复失败后，恢复原导航任务。未注册人员不触发迎宾。系统应避免重复问候，并在导航、语音、动作或识别依赖异常时保持可预测的安全行为。

## 现状与实施边界

- 第一阶段代码范围是“识别服务发出已确认事件，迎宾 skill 播报并执行手部动作”；没有导航状态感知和运动互锁，不能将此等同于已经验证的静止状态。
- 导航暂停/恢复、转向以及静止/安全状态检测保留为后续工作；导航和转向开关打开会被配置校验拒绝。
- `person/mapping.json` 保存注册信息、亲密度和见面计数；旧数据按默认亲密度兼容。`face_enroll` 支持在注册时配置亲密度。
- `FaceRecognitionEngine::onFaceMatch` 通过结构化事件输出已确认识别结果；内置播报已移除，播报由 `g1_face_greeting` 唯一负责。
- `services/face_recognition` 提供事件 MCP capability，由 bridge 读取 VSIS 的 ready/event 协议并将事件交给迎宾 skill。
- `packages/g1_arm_actions` 已提供 `wave_under_head`、`wave_above_head`、单手/双手比心等允许动作，可以由新技能复用。
- `third_party/service-navigation-rbnx` 提供 navigate/status/cancel 和动态速度限制。cancel 是终止而不是暂停；不得将其当成可恢复暂停。速度设为 0 只有在契约和值域、Nav2 实际停止行为及恢复语义经验证后，才可作为临时方案。
- 当前仓库有未提交的用户改动。本计划实施时只修改本功能所需文件，保留并避开其他改动。

## 目标架构

```text
相机
  -> face_recognition 感知服务
       输出已确认的注册人员事件：人员 ID、姓名、问候语、亲密度、置信度、方位、时间戳
  -> g1_face_greeting 编排技能
       去重/冷却 -> 请求导航暂停 -> 面向目标 -> 播报与手部动作 -> 恢复导航
  -> navigation service：保留 run/goal 的 pause/resume
  -> speech service 与 g1_arm_actions：执行播报和动作
```

服务只负责识别和事件语义；技能负责策略和跨能力编排；导航服务负责导航 run 生命周期；手臂动作继续由现有 `g1_arm_actions` 提供。亲密度到动作的映射是迎宾策略，不放进人脸识别算法，也不改变注册人员的身份数据。

## 产品行为与默认策略

### 亲密度档案

- 字段名：`intimacy_level`。
- 类型：整数，范围 `1..5`；注册命令显式设置，不根据姓名或问候语推断。
- 向后兼容：字段缺失的旧记录按手动基础等级 `1` 处理；自动等级仍可按后续有效见面次数提升，且有效等级取基础等级与自动等级的较高值。
- 自动升级门槛在 `robonix_manifest.yaml` 的 `service.face_recognition.config.face.intimacy_upgrade_encounters` 配置，默认累计见面 `[5, 15, 30, 60]` 次分别达到自动等级 `2/3/4/5`；见面次数持久化在 `vsis_video_service/person/mapping.json`，不替代注册时的基础等级设置。
- 显式出现但格式错误或超范围时，注册/加载应给出明确错误，不静默夹取数值。
- 问候语保留现有 `hello` 字段和默认生成行为。

### 动作策略初始建议

动作选择由新迎宾技能的配置映射决定，配置启动时校验每个等级对应的动作必须属于 `g1_arm_actions` 支持列表。实机安全验收前采用低风险动作；映射建议如下，最终以 G1 实机动作安全检查为准：

| 亲密度 | 建议动作 | 说明 |
|---|---|---|
| 1 | `wave_under_head` | 克制、低幅度招手 |
| 2 | `wave_under_head` | 可与等级 1 共用 |
| 3 | `wave_above_head` | 更明显的招手 |
| 4 | `make_heart_with_right_hand` | 单手比心，须确认该预设动作可安全执行 |
| 5 | `make_heart_with_both_hands` | 双手动作，须确认站立状态和动作互斥 |

动作配置需要允许多级共用一个动作；不能因为亲密度高就绕过动作 allowlist、机器人模式检查或安全互锁。

### 迎宾触发默认约束

- 仅已注册且通过多帧确认的人员触发；置信度阈值、确认帧数、事件冷却和同一人重新入场规则均可配置并有边界校验。
- 一次只处理一个迎宾目标；迎宾中到达的事件进入有界策略（建议丢弃并记录），不得无限排队。
- 默认不在急停、手动控制、更高优先级行为或无法确认导航状态时执行迎宾动作。
- 如果没有正在运行的导航任务，可配置为只迎宾而不做暂停/恢复；第一版默认仅在确认存在受管控导航任务时触发，避免与其他未受控运动源竞争。
- 目标方位不可用、过期或超出可信范围时，不盲目旋转；可安全跳过转向并仅在策略允许时播报/挥手，或直接取消本次迎宾。

## 工作阶段

### 阶段 0：接口勘察与决策门

1. 核对实际运行的人脸识别二进制、相机源、相机内参/FOV、当前识别阈值和确认帧配置，明确图像坐标与机器人坐标的定义及正负方向。
2. 查看导航服务 action/client 生命周期与 Nav2 能力，确定保留同一 run/goal 的暂停和恢复实现路径；确认是否可使用 action cancel/resume、controller lifecycle 或受控零速度机制。禁止假设现有 `cancel` 可以恢复。
3. 明确暂停对状态的含义：保存 run id、目标、暂停发起方/令牌、暂停确认、恢复确认；并定义导航自然结束、人工取消、地图切换、重新定位和多方同时暂停时的冲突行为。
4. 检查 speech 的完成语义及 arm action RPC 是“动作已接收”还是“动作已完成”；若只表示接收，查明可靠完成/超时方式。
5. 基于以上勘察冻结 contract、transport 和消息大小/速率，确认服务端持续事件在当前 Robonix runtime 的可行实现方式。若当前 MCP 不支持合适的有界事件流，则选用已有可发现的 gRPC stream 或受控事件通道，不轮询日志。

**阶段出口：**有书面接口草图；pause/resume 在导航服务侧可实现并可验证；方位计算参数或“方位暂不可用”的安全行为已确认。若暂停方案不能保留原导航 run，则先解决该问题，不进入完整迎宾集成。

### 阶段 1：人脸档案和注册工具

1. 扩展 `face_enroll add` 参数，支持注册姓名、照片、问候语、亲密度；确定清晰的 positional/option 格式并更新 usage，避免可选参数顺序歧义。
2. 保存 `intimacy_level` 到对应 `mapping.json` 条目；`list` 展示亲密度；新增/删除/重复注册的行为保持原子且一致。
3. 实现旧映射缺失字段时默认为 1；对类型错误、越界值、重复 ID/姓名和无效 JSON 做明确诊断。
4. 保证更改 mapping 时不破坏现有照片、feature hub ID 对应关系；验证删人后其他共享照片不被误删。
5. 更新服务 README，给出旧记录迁移说明、注册/查询示例、等级定义及备份/回滚方式。

**阶段验收：**旧 mapping 可以读取；新增记录精确保存档案；list 显示等级；非法等级被拒绝且不改坏 feature hub 或 JSON；删除功能回归正常。

### 阶段 2：结构化识别事件

1. 在现有 face recognition package 增加识别结果 capability/IDL，至少提供稳定事件的 `person_id`、`name`、`hello`、`intimacy_level`、`confidence`、人脸框或归一化中心点、采集时间戳和事件 ID。
2. 方位优先由相机内参换算水平 `bearing_rad`，明确坐标系、单位、正负方向和采集时间；若第一版缺内参，则输出带分辨率的归一化中心位置，由迎宾侧使用显式 FOV 配置换算，禁止返回语义不清的像素值。
3. 修改 C++ `onFaceMatch`：保留稳定确认、离场和去抖逻辑；确认成功后发布事件，不直接播报。记录 event ID/人员 ID/置信度等可诊断信息，不把姓名或人脸特征等敏感内容无必要地写入日志。
4. 在 VSIS 与 Robonix bridge 之间定义稳定 IPC。优先选择有界、可检测断连的结构化通道；不解析控制台日志作为业务 API。明确谁拥有 socket、端口配置、连接重试、ready gate、背压、事件过期与进程重启后的行为。
5. bridge 从可信 mapping enrichment 事件，且对 ID 缺失、亲密度无效、JSON/IPC 损坏和断流失败关闭；事件队列有界，优先丢弃过期数据而非积压旧人脸。
6. 更新 service manifest、contract 文档、配置 spec、启动脚本和部署说明；执行官方 codegen，不修改生成文件。
7. 移除语音代理对识别引擎的必需耦合；如需兼容现有独立自动问候，提供显式开关并默认关闭，避免技能播报重复。部署迁移期间明确旧行为是否保持以及如何切换。

**阶段验收：**测试事件包含匹配人员的正确档案和方位；旧人员仍按等级 1 工作；未知人脸不输出迎宾事件；识别服务不会意外自动重复播报；VSIS 断开或异常退出能被检测且不会将陈旧事件继续报告为新事件。

### 阶段 3：导航 pause/resume

1. 在 `third_party/service-navigation-rbnx` 设计 run-scoped pause/resume capability，严格验证目标 run id 和状态；同一暂停请求幂等，错误 run、终态任务和重复/冲突请求返回明确结果。
2. 暂停需有真实停止确认；resume 仅恢复原 goal/run，不创建重复 goal。定义 Nav2 不支持无损暂停时的实现策略，并在 contract 中如实表达语义。
3. 支持暂停所有者/令牌或等效并发控制，防止迎宾恢复操作覆盖人工暂停或其他客户端的暂停意图。
4. 为暂停和恢复设置超时、状态查询及失败处理；服务重启、导航自然终止、急停、地图切换和人工取消时不得错误续跑。
5. 若勘察证明只能短期采用动态限速为零，则将其作为有条件 fallback：先验证允许值域、控制器停止行为、当前 speed limit 的保存/恢复、限速变更冲突和断连恢复；未满足时不启用该 fallback。
6. 更新 Navigation service manifest、IDL、README/CAPABILITY、codegen 和相关测试。

**阶段验收：**仿真/设备上运行中的目标可暂停至底盘确认静止，再恢复同一个目标；多次暂停恢复幂等；自然完成/人工取消后不会被恢复；暂停确认失败时迎宾技能不启动转身/手臂动作。

### 阶段 4：新建迎宾编排技能

1. 新建独立 `packages/g1_face_greeting` skill package，避免把跨服务策略写进 face recognition bridge。
2. 定义技能生命周期和配置：face provider ID、navigation provider ID、speech provider ID、arm skill/provider ID、底盘/转向能力、事件新鲜度、确认阈值、每人冷却、全局冷却、方位 FOV（如需要）、转向速度/容差/超时、动作映射及各 RPC timeout。
3. 实现状态机：

   ```text
   IDLE -> CLAIM_EVENT -> PAUSE_REQUESTED -> PAUSED_CONFIRMED
        -> TURNING -> GREETING_ACTIONS -> RESUME_REQUESTED
        -> RESUMED -> COOLDOWN -> IDLE
   ```

   所有退出路径均经过 cleanup/finally；仅在本次技能确实取得暂停所有权时才请求恢复。
4. 事件处理：验证结构、event ID、时间戳、人员 ID、置信度、亲密度；对重复/过期事件和正在执行时到达的新事件去重/有界丢弃；记录冷却状态。
5. 动作编排：导航暂停确认后才转向；转向使用经过验证的底盘控制能力/导航服务接口；面向误差达到容差或超时后停止转向；语音调用现有 speech speak；按 intimacy mapping 调用 `g1_arm_actions/run`。
6. 定义语音与手臂动作并行或串行策略。初版建议暂停和转向后并行播报与动作（如果关节/语音能力可并行），但必须等两者完成或超时后再恢复；若 G1 动作互斥规则要求串行，则按实机验收调整。
7. 任一依赖失败时仍尽力停止转向并恢复已取得的导航暂停；恢复失败必须报出任务/run id 和明确人工处置建议，不可返回成功。结果未知的语音/动作不自动重试，避免重复问候/挥手。
8. 增加手动禁用迎宾、急停/手动优先、机器人不安全姿态检查等接入点；若现有系统无可发现的安全状态 capability，则明确把实机运行列为阻塞条件，不以本地假状态替代。
9. 更新 `robonix_manifest.yaml` 部署依赖顺序和 provider 选择配置；不写死 provider endpoint，使用 Atlas 按 contract/transport 和可选 provider ID 发现。

**阶段验收：**mock 测试证明事件去重、等级映射、正确顺序、异常清理和恢复失败处理；独立启动/生命周期重复 activate-deactivate 正常；配置错误在 INIT 阶段明确拒绝。

### 阶段 5：系统集成和设备验收

1. 按依赖顺序 build/codegen、boot：相机与 VSIS、speech、navigation pause/resume、G1 arm action、迎宾 skill。
2. 用可控的测试脸/已注册人员验证身份、置信度、bearing 正负方向和角度精度；多人场景确认事件选择规则（如果仍只追踪最大脸，要明确该限制或实现目标锁定）。
3. 验证移动识别后的停止距离、站立稳定性和暂停确认；任何手部动作只能在机器人确实静止且允许的状态下执行。
4. 分别测低/高亲密度动作、播报内容、动作完成时间、重复识别冷却以及转向超时行为。
5. 注入相机断流、事件流中断、语音超时、手臂 action 拒绝、navigation pause 拒绝、resume 超时、Nav2 自然完成/人工 cancel、skill shutdown 等故障，确认安全停止和清理。
6. 记录实机型号/软件版本、配置、验收步骤和结果；模拟通过与真实设备验收分开报告。

**阶段验收：**真实 G1 完整跑通“导航中识别熟人 -> 停稳 -> 朝向 -> 正确问候与亲密度动作 -> 同一导航任务继续”，并通过安全故障注入；未通过的场景保持功能关闭。

## 测试与质量门

- **档案单测：**旧字段默认等级 1；1 和 5 有效；0、6、浮点、字符串和 null 无效；JSON 更新失败不损坏原文件；add/list/del 与 feature hub 映射一致。
- **感知/契约测试：**已识别目标数据正确；未知脸不触发；confirm/cooldown/reentry 行为正确；事件有界、事件过期、断流和异常退出能检测；mapping 不存在对应 ID 时失败关闭。
- **导航测试：**暂停确认、run 状态迁移、幂等、并发暂停所有权、自然终止、人工取消、恢复同一 goal、超时和 provider 重启。
- **技能单测：**每个 intimacy level 映射到预期 allowlisted action；无效等级/动作被拒绝；重复事件不重入；pause 未确认不转向/问候；任何动作错误均清理；resume 只释放本技能拥有的暂停。
- **系统测试：**Atlas contract/transport/provider 发现、生命周期门禁、activate-deactivate-activate、启动部分失败清理及端到端内容验证。
- **设备验收：**验证机器人实际静止、方位精度、动作安全、导航无重复 goal、恢复行为及错误恢复。记录未执行的测试和所需设备条件。

## 风险与处理

| 风险 | 处理 |
|---|---|
| Nav2 没有原生无损暂停，取消后不能恢复相同 run | 阶段 0 先验证实现路径；未解决前不启用移动中迎宾 |
| 摄像头视场/镜像方向不明造成转错方向 | 标定或显式 FOV；单测左右方向，设备低速验证；数据过期则不转向 |
| 识别服务与技能同时播报 | C++ 自动问候默认关闭；唯一播报所有者为迎宾技能 |
| 旧档案没有手动基础亲密度 | 基础等级兼容为 1；累计见面次数仍按既定门槛计算自动等级 |
| 等级映射到高风险手臂预设动作 | allowlist + 实机安全审核；未确认的映射默认退回低风险动作或禁用 |
| 语音/动作 RPC timeout 但实际已执行 | 不自动重试；记录 outcome unknown；恢复导航并通过冷却抑制重复触发 |
| 暂停与人工控制/急停冲突 | pause ownership/token 与优先级；急停/人工控制优先，技能不得自动解除他人暂停 |
| 多人同屏和事件堆积 | 明确目标选择/锁定；有界事件队列、丢弃过期目标、单次只迎宾一人 |
| 部署版本或生成 contract 不一致 | 单包 build/codegen 验证、清晰依赖顺序、端到端 Atlas 检查 |

## 默认决策记录

- 亲密度字段采用 `intimacy_level`，整数 1–5；旧档案默认 1。
- 映射存放于现有 `person/mapping.json`，不另建人员数据库。
- 识别服务不负责播放问候；迎宾 skill 是播报和亲密度动作的唯一决策者。
- 新增独立迎宾 skill；复用现有 speech 与 `g1_arm_actions`。
- 导航 pause/resume 是安全前置能力。未实现可靠暂停和所有权时，不以取消、直接发零速度或未验证的零限速替代。
- 第一个版本每次只处理一个目标，冷却和方位/置信度阈值配置化；实机验收前不自动启用高亲密度动作。

## 完成定义

- 新增人员可在注册时设置 1–5 亲密度，旧人员按等级 1 正常识别，查询列表能核对配置。
- 人脸服务输出有版本化结构、可去重、带时间语义的已确认注册人员事件，不直接触发问候。
- 导航可安全暂停并恢复同一个任务，且能处理人工暂停/取消与自然完成。
- 新技能可靠完成停止、朝向、个性化语音、按亲密度手部动作和导航恢复；错误路径有界且不假报成功。
- 针对性自动化测试、codegen/build、模拟端到端和真实 G1 验收证据分别记录；未完成的设备验收明确标注。
